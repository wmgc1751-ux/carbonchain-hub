# 产品开发文档 · 碳链通 CarbonChain Hub

> 面向工业场景的**联盟链碳资产动态核算可信存证平台**。
> 本文档记录需求、架构、链内核设计、数据库、接口、前端设计、测试与部署。

---

## 一、需求分析

### 1.1 业务背景

全国碳排放权交易市场覆盖发电、钢铁、建材、化工等八大高排放行业，年覆盖排放量超 50 亿吨。
市场运转的地基是**数据**：企业申报的排放量决定配额缺口，缺口决定交易与履约。而碳数据天然存在痛点：

- 由被监管者自行申报，**改一个数就可能少花几百万元**；
- 核查报告签发后仍可能被"二次编辑"，责任无法界定；
- 监管拿到的是二手的 Excel，无法证明未被中间环节调整；
- 公众面对的是黑箱。

### 1.2 功能性需求

| 角色 | 核心诉求 |
| --- | --- |
| 控排企业 | 上报排放、查看碳账本（配额 + 碳信用）、参与配额交易、用碳信用抵销履约缺口、核验自己的链上存证 |
| 核查机构 | 受理核查任务、出具核查报告、报告签发即上链不可抵赖 |
| 监管机构 | 全局驾驶舱、配额分配、交易监管、动态核算监管、联盟链治理、预警处置与闭环 |
| 公众 | 数据公示大屏、区块链浏览器、防篡改实验台 |

### 1.3 非功能性需求

| 维度 | 要求 |
| --- | --- |
| 可信 | 数据上链防篡改、可追溯、可第三方独立验证 |
| 工业适配 | 高排放行业 + 多能源品种 + Scope 1/2 + 真实排放因子 |
| 联盟链范式 | 成员许可制、无挖矿共识、多方持链 |
| 动态核算 | 准实时采数、滚动核算、动态配额缺口预警 |
| 零依赖 | 区块链密码学全部基于 Node 内置 `crypto` 自研，便于讲清原理 |

## 二、系统架构

```
前端（Vue 3.4 单页应用，无构建）
  企业端 / 核查端 / 监管端 / 公众大屏 / 区块链浏览器
        │ REST / JSON（JWT 认证）
后端（Node.js 22 + Express 4）
  路由层 → 业务服务层(anchor / trade / consortium / dynamic / credit)
        → 联盟链内核(crypto-utils / chain / keystore)
        │ mysql2 连接池
MySQL 8.0 —— carbon_chain（22 张表）
```

**关键设计**：前后端同端口、前端无构建步骤 —— `git clone` 后 `npm install && npm run initdb && npm start` 即可运行，部署零障碍。

详细架构图见 README §二。

## 三、联盟链内核设计（技术核心）

### 3.1 密码学原语（全部自研，零第三方依赖）

| 原语 | 实现 | 用途 |
| --- | --- | --- |
| SHA-256 | `crypto.createHash` | 区块哈希、交易哈希、Merkle 根、口令摘要 |
| Merkle 树 | 自研（含 O(log n) 存在性证明） | 区块内交易完整性 |
| secp256k1 ECDSA | `crypto.createSign/Verify` | 钱包、交易签名、出块签名 |
| scrypt | `crypto.scryptSync` | 口令摘要（抗 GPU 爆破） |
| AES-256-GCM | `crypto.createCipheriv` | 私钥库加密落盘 |

### 3.2 共识：PoA 授权证明（联盟链范式）

- 5 个联盟成员节点（监管权重 3、核查 2/1、企业 1、审计 1），出块按**投票权重展开的轮值序列**；
- 出块节点用钱包私钥对区块头签名，全链校验逐块验签并核对出块者是否授权；
- 支持节点申请 → 监管审批 → 授予/吊销出块权。

> PoW 保留在代码中用于兼容历史区块：`calcHash` 按区块 `consensus` 字段分派算法。

### 3.3 全链完整性校验（五道关）

1. 重算哈希；2. 共识规则（PoW 难度 / PoA 出块签名）；3. 出块权归属；4. 前向引用；5. Merkle 根与交易表比对。

### 3.4 防篡改威慑模型

PoA 的防篡改不依赖算力成本，而依赖**签名 + 多副本比对**：改动任一区块会使后缀哈希全变、
其出块签名无法由非授权主体伪造，且链顶哈希与其它成员节点副本不一致会被立即发现。

| 交易 | `trade_order` / `trade_deal` |
| 链 | `chain_block` / `chain_tx` |
| 联盟治理 | `chain_node` / `chain_node_replica` |
| 动态核算 | `cems_reading` / `carbon_dynamic_account` |
| 其他 | `alert_record` / `audit_log` / `notice` |

## 六、前端设计

- **无构建**：Vue 3.4 + ECharts 5.5 本地化于 `public/vendor/`，直接由后端托管；
- **自研设计系统**：`css/app.css` 深色碳黑主题 + `components.js` 组件库（卡片/表格/分页/图表/弹窗/标签）；
- **哈希路由**：`core.js` 提供路由、状态、API 客户端、格式化与字典；
- **核心页面**：企业端 8 页、核查端 5 页、监管端 11 页、公众 2 页，共 32 条路由。

## 九、缺陷修复留痕（部分）

| 缺陷 | 根因 | 修复 |
| --- | --- | --- |
| 链副本同步报 `WRONG_VALUE_COUNT_ON_ROW` | 占位符个数与列数不符（3 vs 4） | 补全占位符 |
| 动态核算全部高风险 | 模拟排放规模与配额不匹配 | 以企业配额为锚生成确定性排放曲线 |
| 采集读数累计值漂移 | `cems_reading` 无唯一约束，重复插入 | 加 `(ent_id, monitor_no, reading_time)` 唯一键 + `INSERT IGNORE` |
| `/chain/validate` 变慢 | PoA 逐块 ECDSA 验签 | 属预期（用签名换挖矿），性能见 §11.3 |
| 撮合并发超卖 | 撮合无事务无锁 | `db.tx()` + `SELECT ... FOR UPDATE` |
