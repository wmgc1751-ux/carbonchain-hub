# 全控件实操检测报告（2026-10-28 · 第二轮）

> **触发原因**：用户在使用平台时截图反馈一个运行时错误
> `Cannot read properties of undefined (reading 'length')`。
> 上一轮"逐页逐按钮审计"只点每页前 8 个按钮、且不碰页签/下拉/搜索/分页，
> 这类交互路径根本没被覆盖。本轮改为**真实浏览器全控件实操**。

---

## 一、方法：真点，不是扫代码

| 手段 | 说明 | 规模 |
| --- | --- | --- |
| 深度实操工具 `tools/_qa/deep-audit.cjs`（本轮新写） | Edge 真渲染，枚举每页**全部**按钮、页签、下拉、搜索框、分页，逐个真实点击 | 5 角色 · 127 页 · **727 个可枚举控件** |
| 分批重枚举机制 | 点击会改页面状态（开弹窗/换页签），一次枚举点到中途即失效。改为每点 6 个就重新导航回本页、重新枚举、跳过已点 | 覆盖率从 40% → **70.4%（512/727 实际点击）** |
| 错误采集增强 | 包装 `App.notify.err`，在异常变成红色 toast 的**那一刻**抓调用栈，直接定位到 view 文件行号 | 捕获到精确行号 |
| 筛选参数矩阵 `tools/_qa/filter-matrix.cjs`（本轮新写） | 列表接口的筛选参数逐个取值打一遍——"只有带参数才出错"的缺陷（本轮发现 1 个） | **69 个参数组合** |
| 针对性复现脚本 `tools/_qa/verify-tamper-fix.cjs` | 复现"篡改→修复"完整交互并断言零错误 | 1 条关键路径 |

**为什么必须这样测**：本轮 3 个缺陷里有 2 个是"浅层测不到"的类型——
一个只在**点完修复按钮之后**才触发，一个只在该列表**选了筛选条件**时才 500。
不带参数扫接口、不点深层按钮，两者都表现为"一切正常"。

## 二、发现并修复的缺陷（3 个真 Bug + 1 个交互缺陷）

### 缺陷 1（用户截图那个）：防篡改实验台点"修复"后抛 TypeError
- **位置**：`public/js/views/explorer.js:442`、`public/js/views/regulator.js:956`
- **根因**：`/chain/repair` 返回 `{ fromIndex, repaired }`，**没有 `validation` 字段**；
  而面板模板无条件读 `panel.value.data.validation.valid` 与 `.errors.length`。
  于是"模拟篡改"正常（tamper 有 validation），一点"修复"就抛
  `Cannot read properties of undefined (reading 'length')`——正是截图里的报错。
- **修复**：按 `panel.value.kind` 分支渲染；repair 时显示"链已按共识重新出块"提示，
  tamper 时才显示校验结果。`vizBlocks` 里的 `.errors` 同样加空值保护。
- **验证**：`verify-tamper-fix.cjs` 真实点击「模拟恶意篡改」→「按共识重新出块并修复」，
  捕获错误数 **0**（修复前该路径必抛）。

### 缺陷 2：企业端上报列表按任何状态筛选都 500
- **位置**：`server/routes/enterprise.js:120`
- **根因**：查询 `LEFT JOIN verifier_org`，两表都有 `status` 列，筛选条件却裸写
  `status = ?` → MySQL 报 `Column 'status' in where clause is ambiguous`。
  **不选筛选条件一切正常**，所以之前的接口扫描（不带参）完全没发现。
- **修复**：过滤列全部加表别名（`r.status` / `r.period` / `r.report_no`）。
- **验证**：DRAFT / SUBMITTED / VERIFYING / APPROVED / period / keyword 全部 200；
  筛选参数矩阵 69 个组合 **0 失败**。

### 缺陷 3：密钥治理页对无权角色展示可点控件
- **位置**：`public/js/views/keymgmt.js:315`
- **根因**：后端 `/keys/rotation-safety-demo` 是 `requireRole('ADMIN')`，
  但前端给**所有角色**都渲染了输入框与"运行轮换安全举证"按钮。
  监管/核查端点下去只得到"当前角色无权访问该功能"——看得见却点不动。
- **修复**：复用文件里已有的 `isAdmin`，非管理员改为只读说明卡片。
- **验证**：监管端重跑，`/keys` 该控件不再出现，异常归零。

### 缺陷 4（工具健壮性）：`real-layer-check.mjs` 首帧未就绪即崩溃
- **位置**：`tools/real-layer-check.mjs:334-368`
- **根因**：`verify:all` 里该套件自行拉起服务，实时引擎首帧未完成时 `metrics=[]`，
  脚本在 `${ir.value}` 处抛 TypeError，导致整条断言链中断，
  指标台账因此报"1 套失败"（实际不是产品缺陷，是检查脚本不够健壮）。
- **修复**：先轮询等待首帧（最多 8 秒），并把断言消息里的取值改为可选链，
  让失败如实计为一条 ✘ 而不是中断。

## 四、仍未覆盖的部分（如实说明）

1. **覆盖率 70.4%**：剩余约 215 个控件未点到，主要是同一页面里
   **落在 DENY 清单的动作**（提交/删除/清缴/下单/审核/导出等写操作，
   会真实改数据，不能在检测中触发）与浮层内的深层控件。
2. **写操作走的是接口层验证**：这些动作由 `verify:all`（286 断言）与
   小程序 46 组自检覆盖，而非浏览器点击。
3. 若要覆盖剩余控件中的**安全写操作**，可对指定页面单独放开清单再跑，
   但每次都要接受数据被写入的事实（并准备好回滚）。

## 五、这次暴露的流程问题与纠正

上一轮报告写"125 页 / 590 按钮 / 330 点击 / 0 异常"，结论偏乐观——
原因是审计工具**每页只点前 8 个按钮**，且完全不碰页签/下拉/搜索/分页。
本轮把"必须真实点击各界面、各功能"固化为两道新工具：
`deep-audit.cjs`（全控件分批实操）与 `filter-matrix.cjs`（参数组合矩阵），
两者都不依赖静态代码阅读。后续任何"是否可以交付"的判断，以这两个工具的输出为准。
