## 二、线上形态与本地形态的差异（本轮最重要的认知）

上一轮的验收是在**本地**跑 `verify:all`（Express + MySQL 双实例）——那套环境里 286 条断言全绿。
但它与线上（Pages Functions → Worker → Turso）**不是同一套代码路径**：

```
本地：  browser → Express (server/routes/*.js) → MySQL 3306/3307
线上：  browser → Pages Functions → worker/routes/*.mjs → Turso
```

`worker/routes/` 只覆盖了 Express 端点的约 **1/3**。于是出现了一类最难发现的故障：
**接口在本地全通、线上 404，而报告写的是"全绿"**。

这不是"实现有 bug"，是**验收口径与实际交付形态脱节**。本轮把线上形态本身作为被测对象，
并新增了 `tools/_qa/live-probe.mjs`（逐个端点打线上、以 404 判定缺失）作为常设检查手段。

### 3.2 阻断级：边缘完全没有链上写入能力

修复前 `worker/` 里**没有任何 `INSERT INTO chain_block`**。也就是说线上"提交上报 → 上链存证"
这条主链路根本走不通；能看到的只是历史区块的读取。

**修复**：新增 `worker/lib/chainwrite.mjs`：

- `appendBlock(db, txs)`：与小程序 Worker、本地 Node 内核**逐字节相同**的哈希口径
  （`payload_hash = sha256(stableStringify)`、`tx_id` 同法、`merkleRoot` 两两拼接、
  `block_hash = sha256(index|ts|root|prev|POA|proposer|nonce)`）；
- 并发防线：`chain_block.block_index` 唯一索引 + 撞高重读 tip 重算重试；
- 写后清缓存：`registerCachePurge()` 钩子，避免"提交成功 #801"与"链概况 #798"同时在屏。

实测：自测脚本一轮产生 30+ 个真实区块（#772 → #805），且全链复算 0 异常。

### 3.3 安全：38 处鉴权被静默绕过

**根因**：`authRequired` 在本项目里是**高阶装饰器**（`authRequired(handler) → handler`），
不是中间件。我在 `biz2.mjs` 里写成了 `r.post(path, authRequired, requireRole(...)(handler))` ——
Router 会依次执行两个 handler，`authRequired` 被当普通函数调用后返回了一个**新函数**（不是 Response），
Router 视为"未拦截"，继续执行第二个 handler。结果是**只校验了角色，没有校验登录态**。

实测证据（修复前）：`ver001`（核查机构）能读到全市场交易委托单；修复后返回空集。

**修复**：全部改为 `requireRole(...)(handler)`（`requireRole` 内部已含 `authRequired`），
共 38 处。并复查了 `biz.mjs` 与 `chain.mjs`，无同类写法。

> 这类缺陷的危险在于它**不会报错**：越权请求返回 200 和正常数据，
> 与合法请求长得一样。只有用另一角色的 token 去打，才看得出来。

### 3.4 角色首页整页空白（4 个）

表面现象：导航栏、页头（用户名/角色）都正常，**主内容区一片空白**，无报错、无提示。
DOM 里是 `<div class="view-fade"><div><!----></div></div>`。

**根因不是组件坏了，是接口契约不完整**：

| 页面 | 前端读取 | Worker 返回 | 结果 |
| --- | --- | --- | --- |
| 企业总览 | `kpi` `trend` `currentQuota` `alerts` `notices` | 只有 `quota` `dynamic` `reports` `openAlerts` | `d.value.trend.map` 抛错 → 整页空 |
| 监管驾驶舱 | `kpi` `trend` `byIndustry` `byRegion` `topEnt` `gapEnt` | 只有 `enterprises` `reports` `quota` | 同上 |
| 机构总览 | `org` `kpi` `monthly` `conclusion` `deviation` `todoTasks` | 只有 `org` `tasks` `reports` | 同上 |
| 市场行情 | `lastPrice` `change` `kpi` `kline` `ccer` | 只有 `price` `recent` | 同上 |

Vue 在渲染函数里抛异常时会吞掉整个子树并渲染注释节点——**接口 200、数据正常、页面全空**，
这是最容易误判成"前端坏了"的一类缺陷。

**修复**：四个接口按本地 Express 契约补齐字段（保留旧字段做兼容）。

### 3.7 缓存造成的"写后读旧值"与"跨用户串数据"

`worker/index.mjs` 的进程内缓存 + 边缘缓存都以 **URL 为键，不含 Authorization**：

- **跨用户串数据**：同一 isolate 内，A 角色的总览页缓存可能被同 URL 的 B 角色拿到；
- **写后读旧值**：`/api/chain/stats` 缓存 60s，提交成功后链概况仍显示旧高度，看起来像没生效。

**修复**：

1. 带 `Authorization` 的请求一律不走缓存（缓存只留给公开只读端点）；
2. `/api/chain/stats` 的 TTL 改为 **0**（它的唯一价值就是"现在链到哪了"，任何正 TTL 都会制造自相矛盾）；
3. `appendBlock` 成功后清空进程内缓存。

### 3.8 演示数据被验证脚本消耗

全流程验证脚本会真实消耗演示数据：企业把 2025/2026 八个季度报满、核查机构把待办全部出结论。
跑几次之后演示就"无空档可演示"了。

**修复**：新增 `tools/_qa/demo-reset-turso.mjs`，把演示所需的最小数据集复位到可重复演示的稳态
（留一个空档季度 + 给演示机构补 2 个待办），**只调状态与指派关系，不删历史数据**。

### 3.9 演示账号入口被配置关闭

登录页的"演示账号一键切换"是评审现场必经路径，但线上 `DEMO_ACCOUNTS` 环境变量残留旧值 `0`，
接口返回 403"演示账号接口已关闭"——代码、部署、日志都看不出问题。

**修复**：移除对该环境变量的依赖，**默认开放**（符合竞赛演示站的交付形态）。

### 3.10 结算账户在云端只有 2 个（本地 56 个）

迁移时未带全，线上交易端开即"可用资金不足：可用 0 元"。

**修复**：`tools/fix-settlement-accounts-turso.mjs`，与本地同口径
（配额总量 × 68.5 元/吨 × 30% 准备金，无配额企业给 5,000 元下限）。
补齐后 60 个账户、余额合计 1.58 亿元，**金额可由配额反算核对**，不是凭空发钱。

### 3.11 演示核查机构没有待办

`ver001` 名下任务全是"已完成"，核查端演示无法走"接单 → 出结论 → 上链"。

**修复**：`tools/_qa/demo-verifier-tasks-turso.mjs`，把其它机构名下"企业已提交、尚未出结论"的
任务重新指派给演示机构（不新建虚构任务）。
