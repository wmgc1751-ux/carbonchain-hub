## 二、发现并已修复的问题（4 项）

### 1. 平台 `/api/enterprise/wallet` 对 admin 角色返回 500（真 Bug）
- **现象**：L3 矩阵扫出。管理员没有企业档案时，`ent.wallet_address` 直接解引用为空值。
- **修复**：`server/routes/enterprise.js` 补 404 守卫，与 `/overview` 的"企业信息不存在"同口径。
- **验证**：admin 调用现返回 `404 {"code":404,"message":"企业信息不存在"}`；ent001 不受影响。

### 2. 小程序本地库缺权威链表，链路接口全部 500（环境代际错位）
- **现象**：本地起服务后 `/mini/v1/chain/stats` 返回 `no such table: chain_block`。
  代码（`src/chain.js`）读写 `chain_block/chain_tx`（与平台 www、线上 Turso 同构），
  而 `sql/01_schema.sql` 还是链统一前的旧代际（只有 `cc_block/cc_tx`）——线上库是
  从平台账本迁的所以正常，本地一建库就断。
- **修复**：①`01_schema.sql` 补建两张权威链表（DDL 与线上同构）；②`init-db.mjs`
  增加幂等后置迁移：`cc_block/cc_tx → chain_*`（列名映射，`from_address` 按
  `cc_enterprise.did → wallet` 换算成 0x 地址，897/903 命中企业，其余 6 笔为
  监管/核查方发起、本就不应匹配）；③对现有库执行同款迁移（158 块 / 903 笔，
  逐块交易数对账 0 孤儿）。
- **验证**：小程序自检 **46/46 通过**（含 #22 区块哈希本地复算、#23 Merkle 根复算、
  #26 载荷复算、#28 伪造哈希判 TAMPER 等阴性与重算用例）。首跑曾 45/46，#11 失败
  正是本 Bug 的另一表现（企业总览 chain.txs 联不上=0），修复后通过。

### 3. 审计工具可点击"模拟恶意篡改"，把真实链改脏（工具缺陷 + 连带事故）
- **现象**：L5 浏览器审计自动点击了 /explorer「防篡改实验台」的"模拟恶意篡改"
  （DENY 正则未覆盖该词），区块 #30 被真实改写，链校验报 HASH_MISMATCH /
  POA_SIGNATURE_INVALID，导致 5 个链套件失败。**从另一个角度这也实测验证了
  防篡改演示真实有效**——改库立刻被三道校验抓出。
- **修复**：①`console-audit.mjs` 的 DENY 正则补 `篡改|改写|重新出块|出块并修复`；
  ②调 `/api/chain/repair` 从 #30 起按共识重算 2137 个区块，链恢复一致。
- **验证**：重跑 `verify:all` 全绿（25 套 / 286 断言 / 0 失败）。

### 4. `/api/regulator/system` 冷查询 6.6 秒（性能观察，未改）
- 全库 31 表逐表 COUNT 所致，命中后正常。首次打开监管端该页会等数秒，属可接受；
  如后续页面加载明显拖慢，可加短 TTL 缓存。
