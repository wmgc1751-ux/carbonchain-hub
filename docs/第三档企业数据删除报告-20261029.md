## 三、链处理的必要说明

**链是不可篡改的，删库不能删链。** 库里删除后，链上仍有 92 笔交易指向这两家企业的
CEMS 批次数据（`payload_json` 里含企业名）。若保留，会出现"链上有存证、库里查不到"
的悬空引用——这比不删更糟，因为它会被误读为"数据被偷偷删除"。

处理方式：**重置链并从创世块重锚现存 4 家企业的全部真实数据**（此前已执行过一次，
流程成熟）。重锚结果：

```
197 笔 = 8（ljgk 浓度批次）+ 184（中国 CEMS 小时）+ 4（活动水平法核算）+ 1（EPA 直测参照）
0 失败
链校验：198 区块 / 197 载荷绑定全部吻合 / 0 异常
```

这比"只删关联交易"更干净：重置后的链里**不存在**任何指向已删企业的记录，
每条交易都能在库里找到对应数据。

## 六、删除过程中修复的两个工具缺陷

### 1. `real-data-audit.mjs` 的 strict 判定前提失效

原判定：`usccInvalid === 0` 即失败——其前提是"库里全是合成企业"（60 家随机信用代码，
几乎无全符可能）。合成企业删除后只剩 4 家真实企业（代码全合法），该条件把
"数据已变干净"误判为失败。

已改为：`usccInvalid > 0` 才失败（存在合成主体混入才报错），并更新了判定文案。

### 2. 同一脚本的真实 CEMS 层识别缺失

它只查 `cems_reading`（平台自举表），得出"真实设备直报 0 条"的过时结论——而真实数据
在 `cems_cn_hourly` 与 `cems_public_reading`。已补充独立查询，现在能正确输出：

```
cems_cn_hourly       126,192 小时 × 4 家（烟气量 76.33 亿m³ · SO₂ 212.7 t · NOx 495.2 t）
cems_public_reading  1,150 条日均浓度 × 4 家
⇒ 真实 CEMS 数据已接入（河北省污染源自动监控信息公开系统 / ljgk 公开平台）
```
