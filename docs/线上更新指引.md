## 二、更新前必须知道的两件事

### 2.1 线上数据库需要重建（现有数据是种子数据）

新版本 schema 从 16 张表扩展到 **22 张表**（新增 `chain_node` / `chain_node_replica` / `cems_reading` / `carbon_dynamic_account` / `credit_asset` / `credit_offset`）。
因此更新后**必须执行一次初始化**：

```
npm run initdb
```

该命令会 `DROP DATABASE` 后完整重建（22 张表 + 造数 + 构建 163 个 PoA 区块 + 23,892 条 CEMS 读数），实测约 4 秒。

> 线上现有数据是 `init-db` 生成的演示数据，**重建不会丢失任何真实业务数据**。

### 2.2 免费实例的临时文件系统

Render 免费实例重启后本地文件会重置，而链上私钥库 `server/keystore.json` 就在本地。
所以首次部署的启动命令建议写成：

```
npm run initdb && npm start
```

这样每次实例重建时，私钥库与链数据一起重来，签名始终能对上。
（若要保留历史链数据，需把 keystore 放到持久化存储，属于 README §九「仍待完善」范畴。）

## 三、更新方式

### 方式 A：推送到你现有的仓库（推荐，链接不变）

你当初是在 Render 上手动创建的 Web Service，它必然绑定了一个代码源（通常是 GitHub / Gitee 仓库）。

**第一步：从 Render 控制台确认仓库地址**

1. 打开 https://dashboard.render.com/ ，进入 `carbonchain-hub` 服务；
2. 左侧 **Settings** → **Build & Deploy**；
3. 找到 **Repository** 一行，它显示的形如 `https://github.com/<用户名>/<仓库名>`。

**第二步：把本地代码推上去**

```bash
cd "D:/workspace/Challenge Cup/碳链通CarbonChainHub"
git remote add origin <上一步的仓库地址>
git push -u origin main
```

> 推送时会要求 GitHub 授权（首次会弹出登录窗口）。若推送被拒（例如远程已有提交），先执行 `git pull --rebase origin main` 再推。

**第三步：触发部署**

- 若该服务开启了 **Auto-Deploy**（默认开启），推送后会自动重新部署；
- 否则到 Render 服务页点 **Manual Deploy → Deploy latest commit**。

### 方式 B：新建一个仓库

如果原仓库已找不到或不便使用：

1. 在 GitHub / Gitee 新建一个**私有**仓库（不要公开，仓库里的业务逻辑和种子数据不宜外流）；
2. 把仓库地址给我，或自行执行方式 A 的第二、三步；
3. 到 Render 服务页 **Settings → Build & Deploy → Repository** 把源切成新仓库。

### 方式 C：不改仓库，只改 Render 环境变量（**不能替代更新**）

仅调整环境变量**无法**让旧代码获得新功能，必须换代码。此方式只在更新代码之后用于收紧配置：

| 环境变量 | 建议值 | 作用 |
| --- | --- | --- |
| `NODE_ENV` | `production` | 触发启动安全自检 |
| `DEMO_ACCOUNTS` | 不设置（或 `false`） | 关闭演示账号接口 |
| `CORS_ORIGINS` | `https://carbonchain-hub.onrender.com` | 显式白名单 |
| `JWT_SECRET` | 随机长串 | 必填，否则拒绝启动 |
| `KEYSTORE_SECRET` | 随机长串 | 私钥库加密口令 |
| `DB_SSL` | `no-verify` | 云库强制 TLS |

> 新代码已做**云平台自动探测**：即使漏设 `NODE_ENV=production`，只要跑在 Render 上，
> 演示账号接口仍会关闭、跨域仍会收紧。上表只是显式声明，不再是安全前提。

## 四、本次安全加固（代码已改，随更新生效）

| 加固点 | 改法 | 实测结果 |
| --- | --- | --- |
| 演示账号明文口令 | 改为「线上默认关闭」：仅显式 `DEMO_ACCOUNTS=true` 时开放；未设置时只有非生产环境开放 | 生产 / 云平台 → **403 已关闭** |
| CORS 回显任意来源 | 生产环境未配白名单时**不下发任何跨域放行头**（前后端同端口，同源请求本不需要 CORS） | 生产 / 云平台 → **不发 `Allow-Origin`** |
| 漏设 `NODE_ENV` 的兜底 | 新增云平台探测（`RENDER` / `DYNO` / `FLY_APP_NAME` / `VERCEL` / `RAILWAY_ENVIRONMENT` / `K_SERVICE`），命中即按生产语义处理 | `RENDER=true` 未设 `NODE_ENV` → **依然 403 + 不发头** |

四组环境实测：

| 环境 | 演示账号接口 | CORS `Allow-Origin` |
| --- | --- | --- |
| 开发模式（无变量） | 200 返回账号 | 回显来源（便于联调） |
| `NODE_ENV=production` | **403 已关闭** | **不发** |
| `RENDER=true`（未设 NODE_ENV） | **403 已关闭** | **不发** |
| `RENDER=true` + `DEMO_ACCOUNTS=true` | 200（显式开启） | **不发** |

前端同步改进：登录页在接口被关闭时不再误报"后端未启动"，改为提示
「当前为线上环境，演示账号列表已按安全策略关闭」。

## 六、常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| 部署后打开是 502 / 启动失败 | 多为环境变量缺失：`JWT_SECRET` 未配置时生产环境会**拒绝启动** |
| 页面能开但数据为空 | 没跑 `npm run initdb`，或云库无建库权限（需 `DB_MANAGED=true`） |
| 链校验 `valid: false` | keystore 与链数据不配对：重新执行 `npm run initdb` |
| 登录页无演示账号列表 | 正常现象，线上已按安全策略关闭 |
| `npm run initdb` 报无权限 | 云库由平台预创建，设置 `DB_MANAGED=true` |
