# 线上部署操作手册（免费方案 · 全程零成本）

> 目标：把「碳链通 CarbonChain Hub」部署到公网，拿到一个 **https 公网域名**，作为作业的**加分项**。
> 预计耗时：**40–60 分钟**（其中等待构建约 10 分钟）。
> 所需准备：一个邮箱、一个 GitHub 账号、你自己电脑上已跑通的本地版本。

## 〇、先弄明白：「域名」到底是什么

作业原文写的是：

> **加分项**：如果能够使用一些免费的服务器/域名来完成线上部署会更好

这句话里有三层意思，逐层拆开：

| 层次 | 说明 | 你需要做什么 |
| --- | --- | --- |
| **必须的** | 把系统真的跑在公网上，任何人打开链接就能用 | 部署到 Render |
| **平台给的** | 云平台会**免费赠你一个二级域名**，形如 `xxx.onrender.com` | 无需任何操作，创建服务后自动分配 |
| **可选的** | 如果你**自己买了独立域名**（如 `carbon-chain.cn`），交作业时把它写上 | **不做也行**，这是加分项里的加分项 |

**结论**：你拿到的域名会是 `https://<你起的名字>.onrender.com` 这种形式。
它是**真实、可公开访问的 HTTPS 域名**，完全满足"免费服务器/域名完成线上部署"的要求。
自己花钱买 `xxx.com` 属于额外锦上添花，本次不做。

   （任何人）        │  Node 22 · 我们的 Express 应用 │

| **Render** | 跑 Node 应用、给公网域名 | 750 小时/月、512MB 内存、100GB 流量、自动 HTTPS | **不需要** |
| **TiDB Cloud Starter** | 当 MySQL 用（协议兼容） | 5 GiB 存储、5000 万 RU/月 | **不需要** |

两个都不需要信用卡。Render 免费实例会在 15 分钟无访问后休眠，下次访问约 30–60 秒冷启动——**这是正常现象，不影响作业验收**。

## 二、第一步：把代码推到 GitHub

你本地项目已经初始化好 git 仓库并完成了首次提交（92 个文件，`node_modules` 和私钥已排除）。现在只需推到 GitHub。

### 2.1 在 GitHub 建一个空仓库

1. 打开 <https://github.com/new>
2. **Repository name** 填 `carbonchain-hub`
3. 选 **Private**（私有，作业代码不必公开）或 Public 都行
4. **不要**勾选 "Add a README file" / ".gitignore" / "license"（重要，否则推送会冲突）
5. 点 **Create repository**

### 2.2 推送代码

在 GitHub 创建完成后，页面上会显示仓库地址。在你的项目目录里执行：

```bash
cd "D:/workspace/MFAD/碳链通-CarbonChainHub-区块链碳数据存证与配额交易平台"

# 把 <你的GitHub用户名> 换成实际用户名
git remote add origin https://github.com/<你的GitHub用户名>/carbonchain-hub.git
git push -u origin main
```

推送时会弹出登录窗口，用浏览器登录 GitHub 授权即可（Git Credential Manager 会自动处理）。

> **验证**：刷新 GitHub 页面，应该能看到 92 个文件。确认**没有** `node_modules` 目录、**没有** `server/keystore.json`。

## 三、第二步：创建免费云数据库（TiDB Cloud）

### 3.1 注册与建库

1. 打开 <https://tidbcloud.com> → **Sign Up**（可用 GitHub 账号一键登录，最快）
2. 登录后进入控制台，点 **Create Cluster**
3. 选择 **Starter**（即免费版；旧界面叫 Serverless）
4. 配置：
   - **Cluster Name**：`carbonchain-db`
   - **Region**：选 `US West` 或 `US East`（免费区在美国；国内访问稍慢但完全可用）
   - **Set Root Password**：设一个密码，**立刻记下来**
5. 点 **Create**，等待 1–2 分钟，集群状态变成 **Active**

### 3.2 拿到连接信息

集群建好后，点集群名进入详情页 → 点右上角 **Connect**：

| 你要记下的字段 | 示例值 | 对应环境变量 |
| --- | --- | --- |
| Endpoint / Host | `gateway01.us-west-2.prod.aws.tidbcloud.com` | `DB_HOST` |
| Port | `4000` | `DB_PORT` |
| User | `3pTAoNNegb47Uc8.root` | `DB_USER` |
| Password | （你刚设的） | `DB_PASSWORD` |
| Database | `test`（默认库） | `DB_NAME` |

> ⚠️ **两个坑，务必注意**
>
> 1. **用户名带前缀**。TiDB Cloud 的用户名形如 `3pTAoNNegb47Uc8.root`，**必须连前缀一起填**，只填 `root` 会认证失败。
> 2. **必须用 TLS**。所以我们要设 `DB_SSL=no-verify`，否则连接会被拒绝。
> 3. **端口是 4000**，不是 3306。

### 3.3 放行 IP（可选）

免费版默认允许所有 IP 访问。如果连不上，在集群页找 **Network / IP Access List**，添加 `0.0.0.0/0`（允许所有）。

## 四、第三步：把数据灌进云数据库

这一步在**你自己电脑上**执行，把本地的 16 张表和 4600+ 行数据搬到云上。

### 4.1 用项目自带的初始化脚本（推荐）

项目已经改造好了，支持直连云数据库。在项目目录打开终端（Git Bash 或 PowerShell）：

```bash
cd "D:/workspace/MFAD/碳链通-CarbonChainHub-区块链碳数据存证与配额交易平台"

# 换成你自己的连接信息
export DB_HOST="gateway01.us-west-2.prod.aws.tidbcloud.com"
export DB_PORT="4000"
export DB_USER="3pTAoNNegb47Uc8.root"
export DB_PASSWORD="你设置的密码"
export DB_NAME="test"
export DB_SSL="no-verify"     # 必须，否则连不上
export DB_MANAGED="true"      # 必须，TiDB 不给建库权限

node server/scripts/init-db.js
```

看到 `✅ 初始化完成` 就成功了。它会自动：
- 建 16 张表
- 生成 4600+ 行仿真数据
- 真实构建区块链（ECDSA 签名 + PoW 出块 + 全链校验）

> **如果报错 `Access denied`**：检查用户名是否带前缀、`DB_PASSWORD` 是否正确。
> **如果报错 `SSL`**：确认 `DB_SSL=no-verify` 已设置。
> **如果报错 `CREATE DATABASE`**：确认 `DB_MANAGED=true` 已设置。

### 4.2 验证数据已就位

```bash
node -e "
const mysql=require('mysql2/promise');
(async()=>{
  const c=await mysql.createConnection({
    host:process.env.DB_HOST, port:+process.env.DB_PORT,
    user:process.env.DB_USER, password:process.env.DB_PASSWORD,
    database:process.env.DB_NAME, ssl:{rejectUnauthorized:false}
  });
  const [t]=await c.query('SELECT COUNT(*) n FROM information_schema.tables WHERE table_schema=?',[process.env.DB_NAME]);
  console.log('表数量:', t[0].n, '(应为 16)');
  const [b]=await c.query('SELECT COUNT(*) n FROM chain_block');
  console.log('区块数:', b[0].n);
  await c.end();
})()"
```

## 五、第四步：部署到 Render

### 5.1 创建 Web Service

1. 打开 <https://render.com> → **Sign Up**（选 **GitHub** 登录，可直接授权读仓库）
2. 进入 Dashboard → 点 **New +** → **Web Service**
3. 选 **Build and deploy from a Git repository** → **Next**
4. 连接你的 GitHub 账号，选中刚推上去的 `carbonchain-hub` 仓库
5. 填写配置（**逐项对照**）：

| 配置项 | 填什么 |
| --- | --- |
| **Name** | `carbonchain-hub` ← **这决定你的域名** |
| **Region** | 选离 TiDB 近的，如 `Oregon (US West)` |
| **Branch** | `main` |
| **Language / Runtime** | `Node` |
| **Build Command** | `npm install` |
| **Start Command** | `npm start` |
| **Instance Type** | **Free** ← ⚠️ 一定要选这个 |

6. **不要**点创建，先往下看环境变量。

> **关于域名**：你填的 Name 会决定域名。填 `carbonchain-hub`，最终域名就是
> **`https://carbonchain-hub.onrender.com`**
> 如果这个名字被别人占用了，Render 会让你改，改成 `carbonchain-hub-2026` 之类即可，
> 域名随之变成 `https://carbonchain-hub-2026.onrender.com`。

### 5.2 添加环境变量（**最关键的一步**）

在创建页面向下滚动到 **Environment Variables**，点 **Add Environment Variable**，逐条添加：

| Key | Value | 说明 |
| --- | --- | --- |
| `DB_HOST` | `gateway01.us-west-2.prod.aws.tidbcloud.com` | 你的 TiDB Host |
| `DB_PORT` | `4000` | TiDB 端口 |
| `DB_USER` | `3pTAoNNegb47Uc8.root` | **带前缀的完整用户名** |
| `DB_PASSWORD` | （你的密码） | TiDB root 密码 |
| `DB_NAME` | `test` | 库名 |
| `DB_SSL` | `no-verify` | 启用 TLS 但不校验证书 |
| `JWT_SECRET` | （随便敲一串长随机字符，如 `cc-hub-2026-x9Kd83mQz7Lp4Rt6`） | **必须改，不要用默认值** |

> `PORT` **不用设**，Render 会自动注入。
> `HOST` 用项目默认的 `0.0.0.0`，已经是对的，无需设置。

### 5.3 创建并等待

点 **Create Web Service**。Render 开始构建，日志类似：

```
==> Cloning from https://github.com/...
==> Running build command 'npm install'...
added 89 packages in 8s
==> Running start command 'npm start'...
⛓  区块链节点已就绪：高度=154 区块=155 交易=911 难度=4
  访问地址: http://localhost:10000
```

看到 `区块链节点已就绪` 且**没有**黄色警告，就说明连上云数据库了。首次构建约 3–8 分钟。

### 5.4 拿到你的域名 ✅

构建成功后，页面顶部会显示：

```
https://carbonchain-hub.onrender.com
```

**这就是你要写进作业提交说明的域名。** 点开它，应该能看到碳链通的首页。

### 5.5 验收检查

依次访问下面几个地址，全部正常即部署成功：

## 六、可选：防止免费实例休眠

Render 免费 Web Service 在 15 分钟无请求后休眠。如果你希望评阅期间始终保持唤醒状态，可以用免费的定时 ping 服务：

1. 打开 <https://uptimerobot.com> 注册免费账号
2. **New Monitor** → 类型选 `HTTP(s)`
3. URL 填 `https://<你的域名>/api/health`
4. 监控间隔设为 **5 minutes**
5. 保存

这样每 5 分钟会有一次请求，实例就不会休眠。免费额度足够。

## 七、可选加分：绑定自己的独立域名

如果你**已经**有独立域名（或愿意花几块钱买一个），可以在 Render 上绑定：

1. Render 服务页 → **Settings** → **Custom Domains** → **Add Custom Domain**
2. 输入你的域名，如 `carbon.carbonchain.cn`
3. Render 会给你一条 CNAME 记录，形如：
   ```
   carbon  →  carbonchain-hub.onrender.com
   ```
4. 到你的域名服务商（阿里云/腾讯云/Cloudflare）的 DNS 解析页，添加这条 CNAME
5. 等待 DNS 生效（几分钟到几小时），Render 会自动签发免费 HTTPS 证书

完成后，`https://carbon.carbonchain.cn` 就能访问。

**渲染平台支持自定义域名且免费签发 SSL**，这一步不需要额外付费给 Render。

## 八、常见问题

**Q1：构建失败，日志显示 `Cannot find module 'express'`**
`package.json` 里必须有 `express` 和 `mysql2` 依赖，且仓库里不能有 `node_modules`。本项目已满足，检查是否误把 `node_modules` 提交上去了。

**Q2：服务起来了但日志报 `⚠ 区块链初始化失败`**
数据库没连上。回到 5.2 逐项核对环境变量，重点检查 `DB_USER` 是否带了前缀、`DB_SSL` 是否设了 `no-verify`。

**Q3：页面能打开，但列表全是"暂无数据"**
数据库连上了但表是空的。回到第四章重新执行一次数据灌入。

**Q4：`/api/health` 返回 500**
如果同时报数据库错误，同 Q2。如果数据库正常，看 Render 日志里的具体报错。

**Q5：免费实例会到期吗？**
Render 免费 Web Service **不会**按月过期，只要 750 小时/月的额度够用就一直免费。
TiDB Cloud Starter 免费版同样是长期免费的（注意：TiDB "Zero" 试用实例是 30 天，**别选错**，要选 **Starter**）。

**Q6：国内访问慢怎么办？**
免费区在美国，国内直连会有延迟。这是免费方案的固有代价，不影响功能验收。如果实在需要，可考虑：
- Cloudflare 免费 CDN 加速（把域名接进 Cloudflare，开代理）
- 或改用国内平台（但通常需要实名+备案，流程长）
