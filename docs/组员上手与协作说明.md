# 组员上手与协作说明

> 给拿到这份源码的组员。读完本文大约 5 分钟，照着做即可在本机把网站跑起来并开始改。
> 项目 = 一个 Node.js 后端 + 一个**不需要编译**的 Vue 前端 + 一个 MySQL 库。

---

## 一、先装两样东西

| 需要 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | **18 或以上** | 装完在命令行敲 `node -v` 能看到版本号即可 |
| MySQL | **8.x** | 默认按 `127.0.0.1:3306`、账号 `root`、口令 `123456` 连接 |

> 口令不是 `123456` 也没关系，见 §五「常见问题」第 2 条。
> 前端用的 Vue / ECharts 已经放在 `public/vendor/` 里，**不用联网下载**。

---

## 二、三步跑起来（Windows 最省事）

```
第 1 步：双击  init-db.bat      ← 建库建表 + 灌演示数据，约 5~15 秒
第 2 步：双击  start.bat        ← 启动服务（首次会自动 npm install）
第 3 步：浏览器打开  http://localhost:8300
```

在命令行里等价的三步：

```bash
npm install          # 只装 5 个依赖：express / mysql2 / ws / vue / echarts
cp .env.example .env # Windows 用 copy .env.example .env
npm run initdb       # 建库 + 灌数据
npm start            # 启动，默认 8300 端口
```

**注意**：`npm run initdb` 会 **DROP 并重建** `carbon_chain` 库，你之前手动写进去的数据会全部清掉。想重置环境就重跑它。

## 四、改动生效方式（记牢这三条，能省你很多抓头的时间）

| 你改了什么 | 怎么生效 |
| --- | --- |
| `public/js/**`、`public/css/**`、`public/index.html` | **刷新浏览器**即可。建议 `Ctrl+F5` 强刷，避免浏览器缓存旧 js |
| `server/**` | **重启 node**（在跑服务的窗口按 `Ctrl+C`，再 `npm start`） |
| `db/01_schema.sql` | 重跑 `npm run initdb`（**会清空并重建数据库**） |
| `.env` | 重启 node |

**本项目没有 webpack / vite，也没有 `npm run build`。** 前端就是一堆普通 `<script>` 标签，源码即运行代码 —— 好处是改一存一刷就能看到效果，坏处是没有打包压缩，改错文件不会报错只会在浏览器 Console 里冒红字，所以**改完请按 F12 看一眼 Console**。

### 顺带说明：`public/carbon-matrix.html` 是个遗留文件

它是一份 2619 行的**独立**「碳矩阵工业大盘」原型页，技术栈与主站不同（React 18 + Tailwind + Babel standalone，全部依赖公网 CDN 加载）。

**全仓搜索没有任何地方引用它**，它也不是任何路由的目标 —— 线上 `/matrix` 实际加载的是 `public/js/views/matrix.js`（Vue 实现，453 行）。

所以：

- 改「碳矩阵工业大盘」请改 **`public/js/views/matrix.js`**，不要改 `carbon-matrix.html`；
- 断网环境下打开 `carbon-matrix.html` 会因 CDN 不可达而白屏，这属正常，不是 bug；
- 保留或删除由你判断 —— 目前确认无任何引用，删除不会影响主站。

## 五、常见问题

**1. 启动报 8300 端口被占用 / 想换个端口**

```bash
set PORT=8400
npm start
```

**2. 数据库口令不是 123456**

命令行临时设：

```bash
set DB_PASSWORD=你的口令
```

或者复制 `.env.example` 为 `.env`，把 `DB_PASSWORD=` 那行改掉（推荐，一次配好长期用）。

**3. 启动报「数据库未初始化」或页面数据全空**

先跑 `npm run initdb`。

**4. 页面白屏 / 图表不显示 / 点了没反应**

- 先 `Ctrl+F5` 强刷；
- 再看 F12 → Console 有没有红字报错，Network 里接口是不是 4xx/5xx；
- 后端窗口有没有异常堆栈。

**5. 登录后提示「当前身份无权访问该模块，已返回你的工作台」**

这是**路由权限机制在正常工作**，不是 bug。权限的唯一判据在 `public/js/app.js` 的 `OPEN_ROUTES` / `EXTRA_ALLOW` / `canEnter()` 里。如果你要新增页面并允许某角色进入，**改这一处即可**，改完可以用 `npm run check:ui` 的「菜单可达性穷举」验证没有破链。

**6. 需要把私钥库文件发给别人吗？**

**不需要。** 链上私钥由 `blockchain/crypto-utils.js` 的 `generateWalletDeterministic(label)` **按标签确定性派生**，所以在任何机器上跑 `npm run initdb` 都会重建出**完全相同的私钥库**。`server/keystore.json` 只应该存在于运行节点本地，**永远不要外发**。

**7. `npm run check:ui` 跑不起来**

它需要一个 Chromium 内核浏览器做无头巡检，Windows 上默认调用**本机 Edge**。没装 Edge 就换用 Chrome 或跳过这项，改用 `npm run check:api`。

## 七、协作约定（几条能避免互相踩脚）

**1. 别把敏感文件提交上去。** `.gitignore` 已经屏蔽了下面三个，请**不要**用 `git add -f` 强行加进来：

- `.env` —— 各人环境不同，只该在自己机器上存在
- `server/keystore.json` —— 链上私钥
- `node_modules/`

**2. 每人在自己机器上把 `JWT_SECRET` 改成随机长串。** 打开 `.env`，把

```
JWT_SECRET=change-me-to-a-long-random-string
```

换成随便一串 32 位以上的字符。**不改也能跑**（代码会回退到内置默认密钥，启动时会打印告警），但那样任何知道你密钥的人都能伪造登录令牌 —— 本地自己玩无所谓，**任何要放到公网的环境必须改**。

**3. 改动前先 `git pull`，改完提交信息写清楚动了哪块。** 建议格式：

```
feat(views): 企业端数据分析页新增排放强度趋势图
fix(server): 修正配额分配接口的越权校验
docs: 补充组员上手说明
```

**4. 建议按模块分工，避免两人同时改同一个文件。** 一个自然的分法：

| 分工 | 负责目录 | 典型任务 |
| --- | --- | --- |
| 前端 A | `public/js/views/` 企业端相关页 + `css/app.css` | 页面布局、图表、交互细节 |
| 前端 B | `public/js/views/` 监管端/核查端相关页 + `components.js` | 组件抽公共、表格与弹窗 |
| 后端 C | `server/routes/` + `server/services/` | 接口逻辑、业务规则、校验 |
| 后端 D | `server/blockchain/` + `db/01_schema.sql` | 链逻辑、表结构、初始化数据 |

如果只有两三个人，就一人前端一人后端，`app.js` / `core.js` / `components.js` 这三个「公共地基」文件提前说好由谁动。

## 八、遇到问题怎么办

1. 先查本文件和 `README.md` 的「常见问题」；
2. 还不行，把**报错原文 + 你刚改了哪个文件 + 复现步骤**发到群里 —— 这三样齐全，别人一眼就能定位；
3. 别只发「跑不起来了」，那需要来回问五轮。
