## 二、院审意见 ①：信任模型硬伤

> **院审原文**：链上锚点与链下明文同库，DBA 一条 UPDATE 即可同时篡改，与"管理员无法事后篡改"声明证据不对等。
> **建议**：链库与业务库物理分离，篡改实验增设"同库同改"攻击用例。

### 整改

1. **账本库搬到独立 MySQL 实例**（端口 3307、独立账号 `cc_ledger`），迁移工具
   `tools/split-ledger-instance.mjs` 逐表校验行数并比对链顶哈希；
2. **代码层跨实例改造**：`server/db.js` 新增 `ledgerOne/ledgerValue/ledgerPaginate/separationFacts`，
   两处跨库 JOIN 拆成应用侧合并；
3. **隔离强度分四档** L0–L3 写进接口与页面，不再用"分离"这种模糊表述；
4. **新增「DBA 凭据越权同改」攻击用例**：用业务侧最高权限账号尝试一条语句改两边。

### 当前状态

```

  改业务明文成功、改账本被拒（连接层：库不在该实例上）
```

对照组同样重要：业务库明文那一步**必须成功**，否则说明业务账号本身有问题，演练结论不成立。

## 四、院审意见 ③：实机测试系自举模拟、无真实企业数据

> **院审原文**：'实机测试'系自举模拟，无真实企业数据。
> **建议**：接入至少 1 家真实企业 CEMS 数据并请第三方复算。

### 整改：可执行的接入通道 + 第三方复算包

`tools/real-cems-ingest.mjs` 支持三种输入（HJ 212 原始报文 / CSV / JSON），设计原则是**不猜测、不补造**：

- 报文缺 CRC 就标未校验，平台不代算；
- 时间不单调就整批拒绝（乱序通常意味着导出范围重叠或多排口混批）；
- 企业未备案就拒绝入库；
- 批次号用内容寻址（`RCEMS-<sha256前24位>`），重复导入天然幂等。

第三方复算包（`--recompute-package`）只含原始读数、复算口径、链上锚点、边界说明；
平台算值单独放 `expected` 并注明"仅供比对，请先独立完成复算"。

### 当前状态（如实）

```
真实接入批次      0 批     batch_no 以 RCEMS- 开头
真实读数          0 条
模拟读数     34,634 条     平台自举生成，非任何设备上报
第三方复算包   已生成
```

### 必须说明的边界

**真正的第三方复算还没有发生。** 通道、复算包、真实性声明都已就绪并验证可用，但需要：
① 一家真实企业提供 CEMS 报文并授权；② 愿意出具复算结论的第三方机构。
这两件事都需要线下推进，不是本机可以替代的。

这一条的处置是：**把"没有真实数据"从"说不清"变成"说清楚且随时能接"**，而不是声称已解决。

## 九、这一轮的整改逻辑

评审最容易追问的是"你说的和做的是不是一回事"。这一轮的处理原则是：

1. **验收口径必须等于交付形态**。上一轮"全绿"是在本地环境跑出来的，而交付的是云端形态——
   这两者之间的 91 个端点缺口，就是"说的和做的不一致"的具体形态。
2. **宁可默认开放，也不要给演示埋一个静默开关**。`DEMO_ACCOUNTS` 那个环境变量，
   代码、部署、日志全都正常，只有现场点下去才发现是 403。这类开关不该存在。
3. **不报错的错最危险**。整页空白、表格空列、越权返回 200——三个都不抛异常。
   本轮的检查手段是"用另一个角色的 token 去打"和"用浏览器真的点一遍"，而不是只跑接口断言。
4. **补齐的东西要说清边界**。边缘端没有私钥，就返回 501 并说明原因，不假装成功；
   真实数据没接入，就在页面上写"尚无接入"，不把模拟读数冒充实机测试。
