## 二、发现的职能冲突

### 【已修复】冲突 1：结算自检污染真实企业配额

**性质**：测试代码侵入生产数据，是本轮最严重的发现。

```js
// ❌ 改造前 settlement.selfTest()
const ents = await db.query('SELECT id FROM enterprise ORDER BY id LIMIT 2');
const [e1, e2] = [ents[0].id, ents[1].id];   // 取库里前两家真实企业
// ...给 e2 插入 1000 t 配额用于测交割
await db.query(`INSERT INTO carbon_quota (...) VALUES (?, 2026, 0, 1000, 0)
                ON DUPLICATE KEY UPDATE available = available + 1000`, [e2]);
// finally 恢复逻辑只回滚了 e1 的 100 t，**没删 e2 的 1000 t**
```

**实测后果**：跑两次自检后，瑞丰环保（ent66）名下出现 **2700 t 无来源配额**。
真实企业凭空多出碳资产——这既污染核算，也可能被误读为"企业持有配额"。

**修复**：自检改用**每次现建、用完即删的隔离企业**（`ent_code` 以 `SELFTEST-` 开头，
状态 DISABLED），真实企业完全不被触碰。验证：

```
自检前：配额 0 | 企业 6
自检结果：13/13 通过
自检后：配额 0 | 企业 6 | 隔离企业残留 0
✔ 零污染
```

## 四、是否需要每项职能都完成闭环？——不建议

### 结论：**不需要，也不应该。**

**理由一：真实业务的闭环必须由企业自己走完，平台不能代劳。**
企业填报、核查机构出结论、监管分配配额——这三件事涉及真实法律责任。
如果平台为了"演示闭环"替企业造数据，就回到了评审最初批评的"自举模拟"。
上一轮已经把所有合成业务数据删除，现在重新造回去等于倒退。

**理由二：闭环的验证方式应该是"隔离环境可跑通"，不是"生产环境有假数据"。**
本轮用隔离测试企业跑通 10/10，这已经是充分的验证——
证明系统能力完整，同时不污染真实数据。这是软件工程的标准做法（测试夹具与生产数据分离）。

**理由三：不同角色的闭环价值不对等，优先级应有差异。**

| 角色 | 闭环价值 | 建议 |
| --- | --- | --- |
| **企业端** | 最高——平台的核心用户，闭环是产品价值所在 | **必须打通**，等企业真实使用 |
| **监管端** | 高——配额分配与履约监管是政策要求 | 必须打通，可与监管方联调 |
| **核查端** | 高——第三方核查是碳市场信任基础 | 必须打通，需真实核查机构入驻 |
| **交易端** | 中——转让交易是增值功能，非核心 | 可延后，待有配额盈余企业 |
| **管理端** | 低——管理员不做业务决策 | 只需配置运维闭环，不需业务闭环 |

**理由四：全闭环的前提是"有真实业务流"，而当前缺的是业务，不是功能。**
再补多少代码都不会让真实企业开始上报数据。当前应做的是推动企业入驻（授权书+账号开通），
技术上则要保证"企业一旦开始用，链路不会断"——这已由 10/10 实测证明。

### 但如果要演示，正确的做法是

在隔离的演示环境中造数据（与生产库分离），或者明确标注"演示数据"。
本轮的做法（每次现建隔离企业、用完即删）就是可复用的模式。

## 五、迭代升级建议（按优先级）

### P0：修正 5 处 ADMIN 隐性白名单

管理员不应能写企业业务数据。建议：

```
settlement L56  →  'ENTERPRISE'          （账户初始化只给企业自己）
mrv L116/183    →  'ENTERPRISE'          （活动数据只给企业）
zk L200/295/471 →  'ENTERPRISE'          （零知识承诺只给企业）
```

若确有运维需要（如管理员代客初始化），应改为"管理员操作需二次确认 + 留痕"，
而不是直接放行。

### P1：为真实企业准备"开户包"

企业一旦拿到授权书，需要能立刻开始用。应准备：
- 企业账号开通脚本（含信用代码校验、链上钱包生成）
- 初始配额分配模板（按行业基准）
- 首个上报单的引导（避免空白页）

### P2：闭环状态看板

在监管端加一页"闭环健康度"：每个企业六环节的完成情况（当前证据链接口已有数据，缺汇总视图）。
让监管一眼看出"哪家企业卡在哪一步"。

### P3：把闭环实测固化为回归套件

`tools/_qa/loop-e2e.cjs` 已经可用，建议加入 `verify:all`，
每次改动都验证闭环不被打断。
