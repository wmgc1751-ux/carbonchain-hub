## 一、软件概述

### 1.1 开发目的

工业企业的温室气体排放正在从「年度自主填报」走向「实时可核验」。但现行企业碳核算体系普遍存在四类结构性问题：

1. **数据不可信** —— 排放量由企业自行填报，源端无硬件级可信采集，事后可被修改；
2. **核算不透明** —— 使用哪个排放因子、走哪条算式、取哪个统计口径，都沉在 Excel 里，第三方无法穿透复核；
3. **存证不可验** —— 即便把数据上了链，往往只锚定一个哈希值；链下原文被改动后，链上无从感知；
4. **口径不可质证** —— 仅电网排放因子就存在「年均 0.5703」「电力二氧化碳 0.5568」「电力碳足迹 0.6205」「区域基准线 OM/BM」多种口径，若平台只给一个数字，评审方无法判断是否被混用。

本软件把上述四项逐一做成**可显式声明、可复核、可证伪**的工程对象，形成一条从「工业现场计量设备」到「联盟链存证」再到「监管穿透式核验」的端到端可信链路。

### 1.2 主要功能

| 序号 | 功能模块 | 功能说明 |
| --- | --- | --- |
| 1 | 边缘感知与设备可信采集 | 以设备 DID 标识计量设备，模拟 TEE/SE 硬件签名，做物料平衡校验；异常设备自动阻断上链 |
| 2 | 多档核算内核 | 支持 Tier 1 缺省因子法、Tier 2 国别参数展开法（NCV×CC×OF×44/12）、Tier 3 CEMS 连续监测三档方法 |
| 3 | 组织碳与产品碳双轨核算 | 组织碳按 ISO 14064-1（自下而上由设备读数积分）、产品碳按 ISO 14067 / GB/T 24067（cradle-to-gate，范围一+范围二） |
| 4 | 不确定度量化 | 蒙特卡洛抽样传播，并以解析解（误差传播律）双向互证，给出一阶敏感性排序 |
| 5 | 排放数据上报与第三方核查 | 企业端提交排放报告，核查机构端受理、出具核查报告，核查报告摘要上链 |
| 6 | 联盟链共识与存证 | 自研区块链内核：PoA 授权证明共识、区块哈希链、Merkle 树、双密码套件（SHA-256/ECDSA 与 SM2/SM3）、五道链上链下校验 |
| 7 | 联盟链成员治理 | 成员的申请、审批、授权出块、权重轮值、资格吊销；各成员节点持全量链副本并同步 |
| 8 | 动态核算与履约风险预警 | CEMS 实测读数按固定步长自动采集 → 滚动核算年度累计排放与期末外推 → 与配额比对自动生成履约风险预警 |
| 9 | 碳资产管理与抵销 | 碳配额账户与分配流水、碳信用资产（CCER / 林业碳汇 / 绿证）登记、碳信用抵销履约缺口（受配额比例上限约束） |
| 10 | 碳配额交易撮合 | 挂单、撤单、价格优先 + 时间优先连续撮合、冻结与解冻、成交即上链存证 |
| 11 | 穿透式验真与数字护照 | 提供四级证据链核验（物理表计采样 → 硬件芯片签名 → 智能合约核算 → 权威节点共识），并支持导出产品碳足迹数字护照 |
| 12 | 公示大屏与区块链浏览器 | 面向公众的数据公示大屏；区块、交易、地址的检索与详情查看，交易详情含 Merkle 存在性证明路径 |
| 13 | 科研验证中心 | 面向评审方的公开验证面板：核算内核复算、不确定度互证、判据可证伪性演示、标准合规映射、性能基准 |

### 1.3 技术特征

| 特征 | 说明 |
| --- | --- |
| 密码学零第三方依赖 | 区块链内核（哈希链、Merkle 树、secp256k1 ECDSA、PoA 出块签名）全部基于 Node.js 内置 `crypto` 自研，未引入任何第三方区块链框架 |
| 国密合规双套件 | 同时支持国际通用套件（SHA-256 + secp256k1/ECDSA）与国密套件（SM3 + SM2）；SM3 输出与 GB/T 32905-2016 附录 A 官方测试向量逐位一致 |
| 五道链上链下校验 | ① 区块头哈希重算 ② 出块签名与授权资格（PoA）或难度前导零（PoW）③ 前向引用 prevHash ④ Merkle 根重算 ⑤ 链下重算绑定 |
| 确定性可复现 | 随机数统一由固定种子（mulberry32, seed=20261011）驱动，跨机器复算结果逐位一致，所有实验结论可复核 |
| 判据可证伪 | 每一项数据自洽判据均经负向注入验证；若一条判据在任何输入下都通过，则不视为有效判据 |
| 前后端分离、无构建步骤 | 前端采用 Vue 3 CDN 全局构建，无需 webpack/vite 打包；后端 Express 提供 REST 接口 |

## 三、安装与部署

### 3.1 获取与安装依赖

```bash
cd 碳链通CarbonChainHub
npm install
```

### 3.2 配置环境变量

复制模板并填写：

```bash
cp .env.example .env
```

| 变量名 | 说明 |
| --- | --- |
| `PORT` | HTTP 服务端口，默认 8300 |
| `HOST` | 监听地址，默认 0.0.0.0 |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | 数据库连接信息 |
| `DB_SSL` | 云数据库启用 TLS 时设为 `true` 或 `no-verify` |
| `DB_MANAGED` | 数据库由平台预创建、当前账号无建库权限时设为 `true` |
| `JWT_SECRET` | 会话令牌签名密钥，生产环境必须改为随机长串 |
| `KEYSTORE_SECRET` | 链上私钥库加密密钥（AES-256-GCM），生产环境必须设置 |
| `CHAIN_CONSENSUS` | 共识算法，默认 `POA` |
| `CHAIN_NODE` | 本节点标识，默认 `node-carbon-01` |
| `DEMO_ACCOUNTS` | 是否开放演示账号列表接口；生产环境建议 `false` |
| `CHAIN_DEMO` | 是否开放链篡改/修复等演示性写接口；生产环境须 `false` |
| `CORS_ORIGINS` | 跨域白名单，逗号分隔 |

> 安全提示：本系统内置启动自检 `assertSecureConfig()`。在生产或云平台语义下，若缺少 `JWT_SECRET` / `DB_PASSWORD` / `KEYSTORE_SECRET`，进程会拒绝启动并打印缺失项，避免以不安全配置带病运行。

### 3.3 初始化数据库

```bash
npm run initdb
```

该命令将建库、建表（共 23 张表）、灌入基准数据、创建创世块、初始化联盟成员节点并完成链副本分发。

### 3.4 启动服务

```bash
npm start          # 生产模式启动器（先自检库结构，已是最新则跳过初始化）
npm run dev        # 开发模式直接启动
```

启动成功后控制台输出：

```
  碳链通 CarbonChain Hub 已启动
  访问地址: http://localhost:8300
⛓  区块链节点已就绪：高度=xxx 区块=xxx 交易=xxx 共识=POA
🔗 联盟链已就绪：授权节点 5 个，副本一致节点 5/5
📈 动态核算引擎已启动：实测读数 xxx 条，覆盖企业 xx 家
```

浏览器访问 `http://localhost:8300` 即进入统一登录页。

### 3.5 云端部署（可选）

系统支持部署到 Render、Railway 等托管平台，数据库使用 TiDB Cloud Serverless 等兼容 MySQL 的云服务。生产启动脚本 `server/scripts/start-prod.js` 会先探测数据库结构版本：若为旧版则执行一次完整初始化，若已是最新版则跳过，从而避免每次冷启动重建全链与演示数据。

| 系统管理 | `ADMIN` | 全部监管端权限，并额外具备链维护（模拟篡改／修复，仅在演示模式开放）能力 |

## 五、功能操作说明

### 5.1 统一登录

访问系统首页进入统一登录页。页面左侧为绿色能源主题动态背景（光伏阵列／风机），右侧为登录表单。输入账号与口令后点击「登 录」，系统校验密码摘要（scrypt）并签发 JWT 令牌，随后按角色跳转至对应工作台。

登录接口带有限流保护：同一 IP 与账号每分钟最多尝试 10 次，超出返回「登录尝试过于频繁」提示。

### 5.2 数据公示大屏（`/screen`）

面向公众的全屏公示页面，展示控排企业数量、链高度实时同步状态、年度排放总量、配额分配与交易概况等关键指标，配以图表轮播。适用于展厅大屏与答辩现场开场。

### 5.3 区块链浏览器（`/explorer`）

提供区块列表、区块详情、交易列表、交易详情、交易池、地址存证查询与全链完整性校验。

- **区块详情**：展示区块高度、区块哈希、前一区块哈希、Merkle 根、共识类型、出块节点、出块签名、交易数量、出块时间与出块耗时。
- **交易详情**：展示交易号、业务类型、业务单号、收发地址、载荷摘要、交易签名，并给出该交易在区块 Merkle 树中的**存在性证明路径**。
- **全链完整性校验**：一键触发五道校验，返回校验结论、已校验区块数、各类校验覆盖计数与异常明细（如有）。接口支持 `?fresh=1` 参数强制实时重算。

### 5.4 科研验证中心（`/verify`）

面向评审专家的公开验证面板，将本系统的全部技术主张摊开为可质证的数据面板，包含六个页签：

1. **核算内核复算** —— 台账自洽性、产品碳内部闭合、组织碳核算、双轨包含性；
2. **不确定度传播** —— 蒙特卡洛抽样与解析解双向互证，可现场调整迭代次数重跑；
3. **判据可证伪性** —— 演示四类故意破坏（篡改总量／改范围占比／删工序段／产品碳放大超组织碳）全部被检出；
4. **标准合规映射** —— GB/T 24067、ISO 14064-1、ISO 14067、GHG Protocol、IPCC 2006、IPCC AR6 GWP100、国务院令 775 号、GB/T 46053-2025、EU 2023/956（CBAM）、GB/T 32905-2016、GM/T 0004 等标准与平台落地位置的对应关系；
5. **性能基准** —— 密码学吞吐、Merkle 建根、签名套件对比、PoA 出块、全链校验、篡改检出对照；
6. **国密合规自证** —— SM3 官方测试向量逐位比对结果。

### 5.5 CEMS 实测流监控（`/cems`）

展示排口连续监测系统（CEMS）的实测读数流，按设备与时间序列呈现烟气流量、温度、压力、含湿量、含氧量、二氧化碳浓度、颗粒物、SO₂、NOx 等参数，并给出由原始读数推导的核算结果，体现「数据由物理量按公式实时推导、非硬编码展示值」。

### 5.6 企业端（`/ent/*`）

| 页面 | 路径 | 功能说明 |
| --- | --- | --- |
| 企业总览 | `/ent/overview` | 年度排放、配额余额、履约缺口的指标卡与趋势图 |
| 碳排放上报 | `/ent/reports` | 新建排放报告（填报能源品种消耗量，系统按排放因子折算），提交后自动上链存证；列表可查看上报单详情与链上存证核验 |
| 动态核算 | `/ent/dynamic` | 展示本企业接入计量设备的 CEMS 读数、滚动核算的年度累计排放、期末外推值与履约风险评估 |
| 碳信用与抵销 | `/ent/credit` | 展示持有的碳信用资产（CCER／林业碳汇／绿证）与已抵销记录，可发起抵销申请 |
| 碳配额账户 | `/ent/quota` | 配额账户概览（累计分配／可用／冻结／已用／买入／卖出）与分配流水 |
| 碳配额交易 | `/ent/trade` | 市场订单簿、我的委托（挂单／撤单）、我的成交记录；支持创建买单与卖单 |
| 数据分析 | `/ent/analytics` | 排放强度、能源结构、同比环比等多维图表分析 |
| 链上身份 | `/ent/wallet` | 展示本企业链上地址、公钥与历史存证列表 |
| 通知公告 | `/ent/notices` | 接收监管端下发的通知公告 |

**典型流程：提交一条排放上报并上链存证**

1. 进入 `/ent/reports`，点击「新建上报」；
2. 填写报告期、数据来源，逐项录入能源品种与消耗量，系统实时折算排放量；
3. 点击「提交上报」，后端构造存证交易 → 用发起方私钥签名 → 进入交易池 → PoA 出块；
4. 列表中出现新记录，点击行内「存证」按钮弹出**链上存证核验**面板，依次展示：物理电表采集、边缘 TEE 签名、合约核算、机构背书上链四级证据链，并给出验签结果、存证数据摘要比对结果与链下业务库一致性比对结果。

### 5.9 联盟链治理

`/reg/consortium` 页面展示联盟成员治理全貌：

- **成员准入**：节点申请 → 审批 → 授予出块权；违规成员可吊销资格，链上校验随之判定其历史/未来出块非法；
- **权重轮值出块**：出块顺序由各成员节点的 `vote_weight` 展开为确定性轮值序列，权重越高出块频次越高；
- **出块签名**：出块节点用自身私钥对区块头签名，全网节点验签确认；
- **链副本分发**：每个成员节点持全量链副本，页面展示各副本的同步高度与一致性。

### 5.10 链完整性校验与防篡改演示

在演示模式下（`CHAIN_DEMO=true`），可通过以下接口演示防篡改机制：

```bash
# 模拟恶意节点直接改写数据库中的区块字段
POST /api/chain/tamper        { "blockIndex": 5, "field": "merkle_root" }

# 模拟只改动链下业务明文、链上锚点保持不动
POST /api/chain/tamper        { "blockIndex": 5, "field": "offchain_payload" }

# 还原链下明细
POST /api/chain/repair-payload { "blockIndex": 5 }

# 重算后缀区块哈希并按共识重新出块
POST /api/chain/repair        { "fromIndex": 5 }
```

第一类篡改会被前四道链上校验捕获；第二类篡改**前四道全部通过**，唯有第五道「链下重算绑定」能够发现——这是本系统在开发过程中实测发现并补齐的关键加固点。修复后重新校验恢复 `valid=true`。

> 安全默认：上述接口在未显式设置 `CHAIN_DEMO=true` 时，于生产与云平台环境一律返回 403，避免破坏性写接口暴露在公网。

## 八、常见问题

**Q1：服务启动后页面空白或接口 502？**
先访问 `/api/health` 确认服务状态。若返回 `status: "UP"` 而页面仍异常，多为前端静态资源未加载或被浏览器缓存，尝试强制刷新（Ctrl+F5）。若为云端首次部署，免费实例冷启动可能需要 30～60 秒。

**Q2：启动时进程立即退出，日志提示「安全配置检查未通过」？**
这是安全自检的正常拦截。请按日志提示补齐环境变量：`JWT_SECRET`、`DB_PASSWORD`、`KEYSTORE_SECRET`。本地开发环境仅告警不阻断，生产与云平台语义下会拒绝启动。

**Q3：登录提示「登录尝试过于频繁」？**
登录接口限流为同 IP 同账号每分钟 10 次，等待 1 分钟后重试。

**Q4：演示账号列表读取不到？**
演示账号接口在生产环境默认关闭（返回 403）。若确需在演示环境开放，需显式设置 `DEMO_ACCOUNTS=true`。该接口另带按 IP 限流（120 次/分钟）。

**Q5：链上校验报「链下重算绑定失配」？**
说明某笔交易的链下业务明文与其链上锚定摘要已不一致。多为演示篡改后未还原所致，可调用 `/api/chain/repair-payload` 从备份还原。

**Q6：换机器部署后链校验失败？**
链上私钥采用**确定性派生**（由标签摘要决定），因此只要各环境使用同一套标签即可派生出逐字节一致的密钥；但 `KEYSTORE_SECRET` 用于加密私钥**文件本身**，更换后需重新生成密钥库文件。此外区块哈希包含时间戳，跨时区部署需保证数据库会话时区一致（系统已在 `syncTimeZone()` 中统一处理）。

**Q7：如何复算实验结论？**
执行 `node scripts/uncertainty.js`（核算与不确定度内核六项验证）、`node scripts/bench-crypto.js`（密码学与链性能基准）、`node scripts/browser-check.js`（全路由与交互回归）、`node scripts/smoke-test.js`（接口冒烟）。所有随机数由固定种子驱动，跨机器结果一致。
