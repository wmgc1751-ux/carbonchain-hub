## 一、开讲前 30 秒（定位陈述）

> "碳链通是一个**面向工业场景的联盟链碳资产动态核算可信存证平台**。
> 它解决的核心问题是：碳市场的数据由被监管者自己申报、极易被修改。
> 我们用区块链给碳数据提供了一个防篡改、可追溯、可第三方独立验证的可信层 ——
> 不是发币，而是让'谁排了多少、谁买了多少'变得不可抵赖。"

## 四、答辩常见提问应答

**Q1：你这也叫联盟链？跟公有链有什么区别？**
> 区别在三点，都能现场演示：① **准入许可制** —— 节点必须申请、经监管审批才能获得出块权（联盟链治理页可看到 PENDING/ACTIVE/REVOKED）；② **无挖矿共识** —— 采用 PoA 授权证明，按成员投票权重轮值出块，出块节点用私钥签名，`/chain/validate` 会逐块验签并核对出块者是否授权；③ **多方持链** —— 5 个成员节点各持一份全量副本，主链与各副本链顶哈希实时比对（副本一致 5/5）。公有链是"无许可 + 挖矿竞争"，我们是"许可 + 授权出块"。

**Q2：数据库被攻陷了，链不也被改了？**
> 这是同库部署的局限，我在 README §九 有说明。但本项目已经在数据模型上落实了联盟链的"多方持链"语义：每个成员节点维护独立的 `chain_node_replica` 副本，任一节点本地库被改，其副本链顶哈希会与主链不一致而被发现。真正投产需要把各节点库物理分离并接入 P2P 广播 —— 这是后续规划。

**Q3："动态核算"到底动态在哪？**
> 传统核算是按季度人工填报（`emission_report.year + quarter`）。我们新增了 CEMS 在线监测通道：排口按 4 小时步长推送实测读数写入 `cems_reading`，定时任务滚动计算年度累计排放与日均速率，据此外推期末排放、算出配额缺口并给出履约风险等级，越限自动生成预警。它和季度上报同为 tCO₂e 口径、可相互印证。

**Q4：你们有几种碳资产？**
> 两类：① **碳配额**（年度分配、可市场交易）；② **碳信用**（CCER 国家核证自愿减排量 / 林业碳汇 / 绿证），可用于抵销履约缺口，抵销不得超过配额的 5%（对标全国碳市场规则），抵销流水上链存证。

**Q5：PoA 放弃了挖矿，安全性靠什么？**
> 靠签名与多副本：出块必须由授权节点私钥签名，全链校验逐块验签；改动任一区块会使后缀哈希全变、签名失效；且链顶一旦与其它成员节点副本不一致立刻暴露。PoA 是 Hyperledger、Quorum 等主流联盟链的选择，牺牲了"无许可去中心化"，换来了联盟场景所需的效率与可控性 —— 这正是联盟链的定位。

**Q6：你们的密码学是调库的吗？**
> 不是。哈希链、Merkle 树（含存在性证明）、secp256k1 ECDSA、scrypt、AES-256-GCM 全部基于 Node 内置 `crypto` 自研，项目依赖只有 express / mysql2 / vue / echarts 四个。

**Q7：能上线跑吗？**
> 功能闭环完整、可运行、可验证；作为课程作品/受控内网试点没问题。作为对外产品还差几块：跨机器 P2P、共享存储限流、链上数据加密、监控告警、容器化部署 —— 详见 README §九与文档目录的部署说明。
