# 部署说明（本地运行 / 局域网演示 / 免费线上部署）

> 配套项目：碳链通 CarbonChain Hub（Node.js + Express + MySQL 8 + Vue 3 无构建前端）
> 结构特点：**单个 Node 进程同时提供 REST API 与前端静态资源**，只有一个端口，部署路径短。

---

## 一、本地运行（最常见）

### 1.1 环境要求

| 组件 | 版本要求 | 本机实测 | 说明 |
| --- | --- | --- | --- |
| Node.js | ≥ 18 | 22.22.2 | 需支持 `crypto.createSign` 与全局 `fetch` |
| MySQL | 8.0 | 8.0.29（`D:\MySQL\mysql-8.0.29-winx64`） | 需已启动，默认 `127.0.0.1:3306` |
| 端口 | 8300 | — | 被占用时用 `PORT` 环境变量覆盖 |

### 1.2 三步启动

```bash
# 1. 安装依赖（生产依赖只有 express 与 mysql2）
npm install

# 2. 初始化数据库：建库建表 + 生成 16 张表仿真数据 + 真实构建区块链
npm run initdb

# 3. 启动服务
npm start            # 等价于 node server/app.js
```

Windows 下也可直接双击 `init-db.bat` 与 `start.bat`（脚本内已设 `chcp 65001`，避免中文乱码）。

启动成功后控制台输出：

```
⛓  区块链节点已就绪：高度=161 区块=162 交易=918 难度=4
────────────────────────────────────────────────────────────────
  碳链通 CarbonChain Hub 已启动
  访问地址: http://localhost:8300
  API 前缀: http://localhost:8300/api
────────────────────────────────────────────────────────────────
```

浏览器打开 **http://localhost:8300** 即可。

### 1.3 可配置项（环境变量）

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `8300` | HTTP 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址 |
| `DB_HOST` / `DB_PORT` | `127.0.0.1` / `3306` | 数据库地址 |
| `DB_USER` / `DB_PASSWORD` | `root` / `123456` | 数据库账号 |
| `DB_NAME` | `carbon_chain` | 数据库名 |
| `JWT_SECRET` | 内置默认值 | 会话签名密钥，**线上部署务必修改** |

示例（数据库口令不是 123456 时）：

```bash
# Windows CMD
set DB_PASSWORD=你的密码 && npm start

# PowerShell
$env:DB_PASSWORD="你的密码"; npm start
```

### 1.4 只用 SQL 脚本还原数据（不跑造数脚本）

```bash
mysql -uroot -p < db/01_schema.sql                       # 建库建表
mysql -uroot -p carbon_chain < db/02_seed_data.sql       # 灌入 16 张表数据
# 或一次性导入结构与数据
mysql -uroot -p < db/03_full_backup.sql
```

> 注意：`02_seed_data.sql` 只含业务数据与已生成的区块，导入后链本身就是完整可校验的；若希望重新出块，执行 `npm run initdb`。

## 二、局域网演示（答辩现场）

1. 查询本机内网 IP：`ipconfig`，找到 IPv4 地址（形如 `192.168.x.x`）。
2. 确认 `.env` 或环境变量里 `HOST=0.0.0.0`（默认已是）。
3. 放行防火墙端口（**需要管理员权限**，非管理员账号可跳过，改由同机演示）：
   ```
   netsh advfirewall firewall add rule name="CarbonChain 8300" dir=in action=allow protocol=TCP localport=8300
   ```
4. 同一局域网内的手机/其他电脑访问 `http://192.168.x.x:8300`。

## 三、免费线上部署（加分项）

系统无需构建产物、无反向代理依赖，任何支持"Node 进程 + 环境变量 `PORT`"的平台都可以直接部署。

### 3.1 通用步骤

```bash
# 1. 推送到代码仓库（GitHub / Gitee / Coding 均可）
git init && git add . && git commit -m "feat: 碳链通平台"
git remote add origin <你的仓库地址>
git push -u origin main

# 2. 在平台上创建 Node 应用，构建命令与启动命令：
#    构建：npm install
#    启动：node server/app.js
#    环境变量：PORT=<平台注入> / DB_HOST / DB_PORT / DB_USER / DB_PASSWORD / DB_NAME / JWT_SECRET
```

### 3.2 云端数据库

在平台侧申请 MySQL 实例（多数平台提供免费额度），把实例的连接信息写入环境变量，然后导入 SQL：

```bash
mysql -h <云数据库地址> -P <端口> -u <用户> -p < db/03_full_backup.sql
```

### 3.3 部署检查清单

- [ ] `PORT` 由平台注入且服务读取的是环境变量（本项目已支持）
- [ ] `JWT_SECRET` 已改为自定义值（不要用默认值）
- [ ] 数据库备份已导入，`/api/health` 返回 `chainHeight > 0`
- [ ] 首页能正常加载 `vendor/vue.global.prod.js` 与 `vendor/echarts.min.js`（本项目依赖本地化，不依赖外网 CDN）
- [ ] 演示账号仍可用：`ent001 / ver001 / reg001`（口令 `123456`），`admin / admin123`
- [ ] 如需保留演示用的"篡改实验台"，确认 `/api/chain/tamper`、`/api/chain/repair` 仅在演示环境开放

## 四、运行时维护

| 场景 | 命令 / 做法 |
| --- | --- |
| 服务自检 | `node scripts/smoke-test.js`（49 条用例，全绿说明接口与链均正常） |
| 前端逐页体检 | `node scripts/browser-check.js`（27 条路由 + 5 项交互，产出截图） |
| 性能采样 | `node scripts/bench.js 15` |
| 看链是否被改过 | 浏览器打开 `/explorer`，页面顶部状态条会显示全链校验结果；或 `curl http://localhost:8300/api/chain/validate` |
| 数据被改乱了 | 重新执行 `npm run initdb`（会删库重建，请先备份） |
| 导出当前数据 | `npm run export-sql`（写回 `db/02_seed_data.sql` 与 `db/03_full_backup.sql`） |
| 端口被占用 | `set PORT=8301 && npm start` |

## 五、常见问题

**Q1：启动报"区块链初始化失败（数据库未初始化？）"**
数据库里还没有 `carbon_chain` 库或表不全。执行 `npm run initdb` 后重启。

**Q2：接口报 `ER_ACCESS_DENIED_ERROR`**
数据库账号口令与默认值不一致。设置 `DB_PASSWORD`（以及必要时 `DB_USER`）后重启。

**Q3：页面能打开但数据全是"暂无数据"**
后端没起来或数据库为空。先访问 `http://localhost:8300/api/health`，若返回 500 则回到 Q1。

**Q4：浏览器控制台报"未注册的组件标签 &lt;x-xxx&gt;"**
说明前端组件注册表里没有该标签。本项目已在 `core.js` 提供组件名解析版 `h`（`App.h`），若新增组件请同步登记到 `components.js` 末尾的 `App.components` 映射表。

**Q5：重复执行自检脚本会不会把数据搞坏？**
不会。自检脚本对"上报单"这类有幂等约束的业务做了空位探测（跳过已占用的年度+季度），篡改实验也会在同一次执行内完成"篡改 → 校验 → 修复"闭环。

**Q6：`npm run export-sql` 报找不到 mysqldump**
该脚本依赖 MySQL 客户端的 `mysqldump`。若未加入 PATH，可在环境变量 `MYSQL_BIN` 中指定 MySQL 的 `bin` 目录（例如 `D:\MySQL\mysql-8.0.29-winx64\bin`）。
