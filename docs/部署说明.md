# 部署说明 · 碳链通 CarbonChain Hub

> 面向「本地运行 / 局域网演示 / 免费云端部署」三种场景的落地指南。
> 服务为**单进程 Node.js + MySQL**架构，前后端同端口（后端直接托管前端静态资源），无构建步骤。

---

## 一、环境要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 18（推荐 20 / 22） | 需支持 `crypto.createSign` 与全局 `fetch` |
| MySQL | 8.0（或兼容的云 MySQL） | 本地默认连接 `127.0.0.1:3306` |
| 浏览器 | Chrome / Edge（支持 ES2020） | 前端为 Vue 3 单页应用 |
| 可选 | ffmpeg | 仅录制演示视频时需要 |

依赖仅 4 个：`express` / `mysql2` / `vue` / `echarts`。

## 二、本地运行（最常用）

### 2.1 三步启动

```bash
npm install          # 安装依赖
npm run initdb       # 初始化：建库建表 + 造数 + 构建联盟链 + 动态核算自举
npm start            # 启动服务（默认 http://localhost:8300）
```

Windows 用户可直接双击 `init-db.bat` 与 `start.bat`（已内置 `chcp 65001`，避免中文乱码）。

### 2.2 数据库口令不是 123456？

```bash
# Windows
set DB_PASSWORD=你的口令
# Linux / macOS
export DB_PASSWORD=你的口令
```

或复制 `.env.example` 为 `.env` 并修改（项目启动时通过环境变量读取，无需额外依赖）。

### 2.3 端口冲突

```bash
set PORT=8400
```

### 2.4 初始化耗时

`npm run initdb` 会真实执行 900+ 次 ECDSA 签名、163 次 PoA 出块、23,892 条 CEMS 实测读数与首轮滚动核算，实测约 **4 秒**。可反复执行（会 `DROP DATABASE` 后完整重建）。

## 三、局域网演示

1. 让服务监听所有网卡（默认已是 `HOST=0.0.0.0`）；
2. 在本机执行 `ipconfig` 取得局域网 IP（如 `192.168.1.20`）；
3. 同网段设备访问 `http://192.168.1.20:8300`；
4. 若被防火墙拦截，放行 8300 端口（Windows 首次运行 Node 时通常会有弹窗，选择"允许专用网络"）。

> 演示账号见 README §7.3；登录页已内置"演示账号一键切换"，现场无需手动敲账号。

## 四、免费云端部署（Render + 云数据库）

> 本项目为**临时文件系统**托管而设计：所有状态都在数据库里，进程重启不丢数据。

### 4.1 数据库（二选一）

- **TiDB Cloud Serverless**（推荐，含免费额度）：创建 Serverless 集群，获取 Host / Port / User / Password；
- **其他托管 MySQL**：Aiven、PlanetScale（注意无 `CREATE DATABASE` 权限时需开 `DB_MANAGED`）。

免费实例通常**强制 TLS** 且不提供 CA 证书，因此：

```
DB_SSL=no-verify      # 启用 TLS 但不校验证书（免费实例常用）
DB_MANAGED=true       # 库由平台预创建、当前账号无 CREATE/DROP DATABASE 权限时开启
```

### 4.2 服务（Render / Railway / Fly.io 等）

| 配置项 | 值 |
| --- | --- |
| Build Command | `npm install` |
| Start Command | `npm run initdb && npm start`（首次）或 `npm start`（之后） |
| 环境变量 | 见下表 |

| 环境变量 | 示例 | 说明 |
| --- | --- | --- |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | 云库控制台提供 | 数据库连接 |
| `DB_SSL` | `no-verify` | 云库强制 TLS |
| `DB_MANAGED` | `true` | 无建库权限时 |
| `JWT_SECRET` | 随机长串 | **必填**，否则令牌可被伪造 |
| `KEYSTORE_SECRET` | 随机长串 | 链上私钥库 AES-256-GCM 加密口令 |
| `CORS_ORIGINS` | `https://你的域名` | 收紧跨域白名单 |
| `NODE_ENV` | `production` | 触发启动安全自检 |
| `CHAIN_CONSENSUS` | `POA` | 共识模式（默认 PoA） |
| `CEMS_INTERVAL_MS` | `60000` | 动态核算滚动间隔（毫秒） |
| `DEMO_ACCOUNTS` | `false` | 生产关闭演示账号接口 |

### 4.3 时区（重要）

数据库驱动固定使用 UTC（`timezone: 'Z'`），且链内核在读写前执行 `SET time_zone = '+00:00'`。
**不要**把时区改成 `local` —— 区块哈希的输入包含绝对秒数时间戳，任何一次本地时区换算都会让
「本机 MySQL」与「云 MySQL（UTC）」反解出不同秒数，导致全链校验失败。

### 4.4 免费托管的注意点

- **临时文件系统**：不要依赖本地文件持久化；私钥库 `server/keystore.json` 会在每次重新部署时重置，
  因此初始化（`initdb`）必须与新实例配对执行，否则旧链的签名无法复现；
- **冷启动**：免费实例会休眠，首次访问需等待数十秒；
- **实例数保持 1**：本项目为单进程单例架构（链实例在内存），多实例会导致内存链不一致。

## 五、生产化检查清单

上线前逐项确认：

- [ ] `NODE_ENV=production`，启动时会自动校验 `JWT_SECRET` / `DB_PASSWORD` / `KEYSTORE_SECRET` 是否配置，缺失则**拒绝启动**；
- [ ] `JWT_SECRET`、`KEYSTORE_SECRET` 为随机长串，且**未写入仓库**；
- [ ] `DEMO_ACCOUNTS` 关闭（或不设置）；
- [ ] `CORS_ORIGINS` 显式配置为前端域名；
- [ ] 数据库账号最小权限（避免使用 root）；
- [ ] 已规划数据库备份（链上链下同库时，备份即备份了链）；
- [ ] 若对外提供服务，按 README §九"仍待完善"补齐：跨机器 P2P、共享存储限流、链上数据加密、监控告警。

## 六、运行时维护与故障排查

### 6.1 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `Unknown database 'carbon_chain'` | 未初始化，先跑 `npm run initdb` |
| 启动报数据库连接失败 | MySQL 未启动 / 口令不对 / 端口不是 3306 / 云库未放行 IP |
| 中文命令行乱码 | 使用 `start.bat`（已 `chcp 65001`）或先执行 `chcp 65001` |
| 8300 端口被占用 | `set PORT=8400` 后重启 |
| 全链校验失败 | 检查是否混用了不同时区/不同机器的库；或链曾被手工篡改，可调 `/api/chain/repair` 修复 |
| 联盟节点副本不一致 | 调 `POST /api/consortium/sync` 一键追平 |
| 想清空重来 | `npm run initdb` 会 `DROP DATABASE` 后完整重建 |

### 6.2 健康检查与可观测

- `GET /api/health`：返回服务状态、链高度、节点名、共识模式 —— 可直接接云平台探针；
- 访问日志：所有 `/api/**` 请求打印方法、路径、状态码、耗时；
- 审计日志：关键写操作落 `audit_log` 表，监管端"操作审计日志"页可查。

### 6.3 数据备份

```bash
# 结构与数据一体化导出（db/03_full_backup.sql 即由该脚本生成）
npm run export-sql
```

链上链下同库，因此**备份数据库即备份了整条联盟链**。恢复后调用 `/api/chain/validate` 应返回 `valid=true`。
