# 答辩现场「离线应急包」操作手册

> 目的：把"答辩现场断网/服务器抽风"这个最大不确定性，压缩成三条命令。
> 适用：碳链通 CarbonChainHub 校赛答辩（2026-10-18）及任何现场演示。

## 三级降级策略（按可靠性从高到低）

| 层 | 形态 | 依赖 | 起法 | 能演示什么 |
| --- | --- | --- | --- | --- |
| **第 1 层** | 线上静态站 | 仅需外网 | 浏览器开 `www.carbonchain.dpdns.org` | 读操作 100%（五端登录、看板、浏览器、验证中心） |
| **第 2 层** | 本地静态站 | 仅需本机 | `npm run offline`（端口 8899） | 同上，断网可用 |
| **第 3 层** | 本地全栈 | 本机 MySQL | `npm run offline -- full`（端口 8300 + 9100） | 全部 + 真落库写入 + 真 HJ 212 设备接入 |

## 常用命令

```bash
# 健康自检：一键看四层谁在线
npm run offline:health

# 第 2 层：起本地静态站（断网首选，5 秒起）
npm run offline

# 第 3 层：起本地全栈（需要演示"写操作真落库"或"设备真接入"时）
npm run offline -- full

# 一键复现全部验证证据（9 秒，108/108）
npm run verify:report

# 真实设备端接入证据（需第 3 层已起，5/5）
npm run evidence:device
```

## 现场决策树

```
答辩现场
 ├─ 有网 → 第 1 层（直接开浏览器）
 ├─ 断网但只需演示"看" → 第 2 层（npm run offline）
 └─ 断网且要演示"写入/设备接入" → 第 3 层（npm run offline -- full）
```

## 注意事项

1. **第 3 层依赖本机 MySQL**：`npm start` 需 `db` 可用（`init-db.bat` 已备）。若现场 MySQL 未起，退到第 2 层。
2. **第 2 层写操作不落库**：静态层读操作 100% 可用，写操作响应真实但刷新回快照基准态——**这不是缺陷，是双模设计的预期行为**，答辩时如需说明可引用《步骤四》§三。
3. **端口冲突**：8899 / 8300 / 9100 被占时，可用 `OFFLINE_STATIC_PORT` / `OFFLINE_FULL_PORT` / `OFFLINE_TCP_PORT` 环境变量覆盖。
4. **首选第 1 层**：线上站已过 47 页 PASS 巡检，是最省心的选择；第 2/3 层是保险，不是默认。
